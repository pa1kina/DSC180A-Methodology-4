**1. What is the most interesting topic covered in your domain this quarter?**  

In my domain this quarter, the most interesting topic was learning about and contributing to strict time-based data. Since data leakage is one of the most obvious and serious problems for agent prediction accuracy, the available_at value must be calculated/sourced extremely meticulously. In a way, we're using scrapers and past website snapshots to recreate the past in a contained environment, which is a very cool concept of itself. For this to be done in the most accurate way, I learned about WorldReset concepts such as available_at, Records, Vintages, and Gaps to ensure that the agents cannot "peek" at information in their relative future. This added an additional layer of consideration compared to my previous classes, where time was simply a potential feature, not dependent on the exact "time tick" the agent is currently at.

**3. What is a potential change you'd make to the approach taken in your current Quarter 1 Project?**  

One thing I've noticed is that reporting licensing information is heavily checked by tests, more than I'd anticipated. However, despite the very many branches that fellow teammates are working on and the even larger amount of sources we're getting though, there is a single licensing document for all sources. When moving my progress code to a smaller repository with my submission group for the checkpoint, I realized I had to manually add in each license info section to the licensing file from each branch, which is a hassle. I think it would be more organized to have the licensing information in a separate unique file for each GitHub branch/source, and a separate compiler that adds it into one document in a replicable way based on timestamp. Overall, it would be helpful to create a checklist for each source at the beginning so that the adapter, tests, samples, documentation, licensing information, and integration tests are completed together.
